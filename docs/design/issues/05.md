# Implement balance overview and contribution explanation

> Completed specification archive. Issue #18 was delivered in [PR #36](https://github.com/haggaikaunda/kami-split/pull/36). The original scope and unchecked criteria below are retained for traceability, not an active task list. See the [completion record](../implementation-plan.md).

GitHub issue: [#18](https://github.com/haggaikaunda/kami-split/issues/18). Parent: [#13](https://github.com/haggaikaunda/kami-split/issues/13). Design gate: [PR #12](https://github.com/haggaikaunda/kami-split/pull/12).

## User outcome

Household members understand the current balance and how it was produced.

## References

- [ux-spec.md#h01-overview](../ux-spec.md#h01-overview)
- [prototype-verification.md](../prototype-verification.md)

## Included behavior

Balance sentence/zero state, explanation, expense contributions, recent activity and clear add/repayment navigation; reserve chart placement for its separate issue.

## Exclusions

No chart implementation in this issue, budgets, aggregate currency conversion or duplicate Balances destination.

## Acceptance criteria

- [ ] Seed shows Kaunda owes Mizenin $42.18; explanation reconciles allocations, paid expenses and net repayments.
- [ ] Contributions exclude repayments; stale/loading/empty/error states never invent a settled balance.
- [ ] Use names from members; three-member fixture renders readable positions/direct obligations without a simplified payment plan.
- [ ] Recent expense actions preserve overview context through detail; mutation invalidation updates balance, contributions and activity.

## Mobile, desktop and accessibility

Apply the shared responsive/accessibility rules: phone-first, desktop context preserved, keyboard operation, labels/errors, 44px targets, visible focus, non-color status and correct focus restoration. Verify the relevant journey at 390px and 1280px; no clipped controls at 320px or 200% text.

## Required tests

Domain-backed view tests for seed totals, zero/reversed balance, three members, loading/errors and invalidation; phone/desktop P01. Run `pnpm format:check`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm build`; obtain independent testing and final-diff review per AGENTS.md.

## Edge states

Cover relevant loading, empty, filtered-empty, invalid input, denied/unavailable, pending, failed and stale states with named seed scenarios. Do not show a fake zero balance while loading or rely on a toast as proof of mutation.
