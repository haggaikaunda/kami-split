# Implement repayment recording with balance preview

> Completed specification archive. Issue #23 was delivered in [PR #40](https://github.com/haggaikaunda/kami-split/pull/40). The original scope and unchecked criteria below are retained for traceability, not an active task list. See the [completion record](../implementation-plan.md).

GitHub issue: [#23](https://github.com/haggaikaunda/kami-split/issues/23). Parent: [#13](https://github.com/haggaikaunda/kami-split/issues/13). Design gate: [PR #12](https://github.com/haggaikaunda/kami-split/pull/12).

## User outcome

Users record money already repaid and understand its effect before saving.

## References

- [ux-spec.md#s01-record-repayment](../ux-spec.md#s01-record-repayment)
- [screen-flows.md#n06-repayment-and-account-transitions](../screen-flows.md#n06-repayment-and-account-transitions)

## Included behavior

Sender/recipient, amount/date/note, before/after preview, overpayment acknowledgment, safe mutation and read-only repayment detail.

## Exclusions

No trip-scoped debt, payment processing, methods, repayment edit/delete or bank integrations.

## Acceptance criteria

- [ ] Pair defaults match debt; choose distinct members and valid positive amount. Three-member fixture requires explicit sender/recipient.
- [ ] Preview correctly handles partial, exact and overpayment with named direction; reversal requires acknowledgment. Copy states no money moves.
- [ ] One operation creates one repayment event and equal/opposite position updates; spending/contributions remain unchanged.
- [ ] Save/cancel returns to original overview/trip context; history repayment detail is readable and closes back to filtered list.
- [ ] Pending/unknown outcome preserves input and resolves original operation. Mobile full-screen/desktop dialog with label/focus/dirty guards.

## Mobile, desktop and accessibility

Apply the shared responsive/accessibility rules: phone-first, desktop context preserved, keyboard operation, labels/errors, 44px targets, visible focus, non-color status and correct focus restoration. Verify the relevant journey at 390px and 1280px; no clipped controls at 320px or 200% text.

## Required tests

Unit/integration direction/partial/full/overpayment/zero/same-member cases; E2E P03, repeat submit and timeout-after-commit. Run `pnpm format:check`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm build`; obtain independent testing and final-diff review per AGENTS.md.

## Edge states

Cover relevant loading, empty, filtered-empty, invalid input, denied/unavailable, pending, failed and stale states with named seed scenarios. Do not show a fake zero balance while loading or rely on a toast as proof of mutation.
