# Implement spending charts and contextual drill-downs

> Completed specification archive. Issue #27 was delivered in [PR #47](https://github.com/haggaikaunda/kami-split/pull/47). The original scope and unchecked criteria below are retained for traceability, not an active task list. See the [completion record](../implementation-plan.md).

GitHub issue: [#27](https://github.com/haggaikaunda/kami-split/issues/27). Parent: [#13](https://github.com/haggaikaunda/kami-split/issues/13). Design gate: [PR #12](https://github.com/haggaikaunda/kami-split/pull/12).

## User outcome

Users explore household and trip spending over time with exact, inspectable data.

## References

- [ux-spec.md#h02-spending-charts](../ux-spec.md#h02-spending-charts)
- [screen-flows.md#n04-chart-drill-down-chain](../screen-flows.md#n04-chart-drill-down-chain)

## Included behavior

Daily/monthly/yearly household chart, period/scope controls, exact table, contributing records drill-down; trip daily and category charts.

## Exclusions

No budgets, trend forecasts, conversion, exports or unrelated analytics dashboards.

## Acceptance criteria

- [ ] Daily month / monthly year / five-year views include zero periods and correct next/previous increments; preserve scope/period.
- [ ] Household vs own allocated share is explicit; expense dates/current revisions drive sums; repayments/deletions excluded. USD labeled.
- [ ] Every bar supports keyboard/touch activation and exact amount/count; table offers same data. Visual scale is truthful with separate hit areas if needed.
- [ ] Drill-down → expense → mutation → Back recomputes same bucket including newly empty results; browser Forward restores correct per-visit context.
- [ ] Trip charts cover travel range plus recorded out-of-range expenses, including zero days; long ranges are fully represented with clear scale/scroll behavior.

## Mobile, desktop and accessibility

Apply the shared responsive/accessibility rules: phone-first, desktop context preserved, keyboard operation, labels/errors, 44px targets, visible focus, non-color status and correct focus restoration. Verify the relevant journey at 390px and 1280px; no clipped controls at 320px or 200% text.

## Required tests

Bucket unit tests across month/year/leap/date boundaries, scope/category sums, zero/large values, mutation invalidation; E2E P08/N04 plus keyboard/table/mobile checks. Run `pnpm format:check`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm build`; obtain independent testing and final-diff review per AGENTS.md.

## Edge states

Cover relevant loading, empty, filtered-empty, invalid input, denied/unavailable, pending, failed and stale states with named seed scenarios. Do not show a fake zero balance while loading or rely on a toast as proof of mutation.
