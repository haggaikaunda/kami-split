# Establish design tokens and shared accessible UI primitives

## User outcome

Every journey uses one consistent, accessible visual language.

## References

- [ux-spec.md#shared-visual-and-accessibility-rules](../ux-spec.md#shared-visual-and-accessibility-rules)
- [assets/README.md](../assets/README.md)

## Included behavior

Tokens and reusable controls: buttons, fields, member/avatar, cards, dialog/panel, confirmations, errors/toasts, skeleton/empty state and chart/table presentation building blocks.

## Exclusions

No journey implementation, new reports, speculative design system, external asset licensing assumptions or production persistence.

## Acceptance criteria

- [ ] Extract intentional colors, typography, spacing, radius, focus and breakpoint tokens; avoid copying override-heavy prototype CSS.
- [ ] Controls have labels, error relationships, visible focus and minimum 44px targets; dialog traps focus and restores a logical trigger.
- [ ] Money display supports exact formatted values/tabular figures; icons/status do not rely on color alone.
- [ ] Render examples at 320/390/1280px and 200% text without clipped controls; font/photo failures have usable fallbacks.

## Mobile, desktop and accessibility

Apply the shared responsive/accessibility rules: phone-first, desktop context preserved, keyboard operation, labels/errors, 44px targets, visible focus, non-color status and correct focus restoration. Verify the relevant journey at 390px and 1280px; no clipped controls at 320px or 200% text.

## Required tests

Component interaction tests for keyboard/dialog/focus/error semantics; manual contrast and text-size check with screenshots. Run `pnpm format:check`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm build`; obtain independent testing and final-diff review per AGENTS.md.

## Edge states

Cover relevant loading, empty, filtered-empty, invalid input, denied/unavailable, pending, failed and stale states with named seed scenarios. Do not show a fake zero balance while loading or rely on a toast as proof of mutation.

## Dependencies and readiness

Blocked until the design/documentation PR is reviewed and merged, stable main references are verified, and this issue is approved. No implementation prerequisite beyond the design merge gate. Existing pilot issues #6–#9 are separate and not prerequisites.
