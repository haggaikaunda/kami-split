# Implement trips list and create-trip flow

## User outcome

Users can organize shared travel spending into recognizable trips.

## References

- [ux-spec.md#t01t02t03-trips](../ux-spec.md#t01t02t03-trips)
- [screen-flows.md#n05-trip-chain](../screen-flows.md#n05-trip-chain)
- [assets/README.md](../assets/README.md)

## Included behavior

Trip cards, approved sample covers/defaults, status filters and create name/destination/dates form.

## Exclusions

No budgets, itinerary, cover upload/edit, booking or trip financial duplication.

## Acceptance criteria

- [ ] Show Maui Sep 5–13 2026, Tahoe Aug 14–17 2026 and Porto May 12–18 2027 with totals derived from shared expense records.
- [ ] All/Upcoming/Past filters follow injected clock; in-progress appears in All. No hardcoded status per sample.
- [ ] Require name/valid dates/end >= start. Create opens new trip overview destination with empty state; preserve dirty input on failure.
- [ ] Cards work on phone/desktop, have descriptive link names and resilient image fallback/credits; new trip uses default cover.

## Mobile, desktop and accessibility

Apply the shared responsive/accessibility rules: phone-first, desktop context preserved, keyboard operation, labels/errors, 44px targets, visible focus, non-color status and correct focus restoration. Verify the relevant journey at 390px and 1280px; no clipped controls at 320px or 200% text.

## Required tests

Trip form/status/aggregate tests including boundary dates and future year, empty list/filter and denied command; E2E create-to-empty-trip transition once detail lands. Run `pnpm format:check`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm build`; obtain independent testing and final-diff review per AGENTS.md.

## Edge states

Cover relevant loading, empty, filtered-empty, invalid input, denied/unavailable, pending, failed and stale states with named seed scenarios. Do not show a fake zero balance while loading or rely on a toast as proof of mutation.

## Dependencies and readiness

Blocked until the design/documentation PR is reviewed and merged, stable main references are verified, and this issue is approved. Depends on UX-02, UX-03, UX-04. Existing pilot issues #6–#9 are separate and not prerequisites.
