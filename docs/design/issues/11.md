# Implement chronological and filterable financial history

## User outcome

Users can explain how the current balance was produced from all financial activity.

## References

- [ux-spec.md#a01-history](../ux-spec.md#a01-history)
- [screen-flows.md#n01-contextual-expense-entry-and-backforward](../screen-flows.md#n01-contextual-expense-entry-and-backforward)

## Included behavior

Event feed with expenses, edits, deletions, repayments, text/type/member filters and links to current record/selected revision.

## Exclusions

No new date-range filters, pagination requirement, export, reporting dashboard or changes to History label.

## Acceptance criteria

- [ ] Order event timestamp then stable sequence; distinguish event date from expense effective date and disambiguate years.
- [ ] Search/type/member semantics match spec; selected filters persist across detail/edit/delete/repayment round trips.
- [ ] Edits/deletions remain auditable even when record is inactive; an event opens relevant immutable revision within current detail.
- [ ] Empty feed offers first expense; filtered-empty offers Clear filters; loading/error announcements preserve user context.

## Mobile, desktop and accessibility

Apply the shared responsive/accessibility rules: phone-first, desktop context preserved, keyboard operation, labels/errors, 44px targets, visible focus, non-color status and correct focus restoration. Verify the relevant journey at 390px and 1280px; no clipped controls at 320px or 200% text.

## Required tests

Adapter/view tests for event ordering, same timestamp, all filters/member roles, year labeling, tombstones and selected revision; E2E P05 with Back/Forward and focus. Run `pnpm format:check`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm build`; obtain independent testing and final-diff review per AGENTS.md.

## Edge states

Cover relevant loading, empty, filtered-empty, invalid input, denied/unavailable, pending, failed and stale states with named seed scenarios. Do not show a fake zero balance while loading or rely on a toast as proof of mutation.

## Dependencies and readiness

Blocked until the design/documentation PR is reviewed and merged, stable main references are verified, and this issue is approved. Depends on UX-02, UX-03, UX-04, UX-07, UX-10. Existing pilot issues #6–#9 are separate and not prerequisites.
