# Implement safe expense editing and revision conflicts

> Completed specification archive. Issue #21 was delivered in [PR #41](https://github.com/haggaikaunda/kami-split/pull/41). The original scope and unchecked criteria below are retained for traceability, not an active task list. See the [completion record](../implementation-plan.md).

## User outcome

Users can correct an expense while preserving history and other members’ changes.

## Included behavior

Prefilled shared form, entire-record validation, expected version, before/latest/draft conflict comparison and explicit reapply.

## Exclusions

No deletion confirmation or new add-flow redesign, repayment correction, database or silent last-write-wins.

## Acceptance criteria

- [ ] Prefill every field and participant membership independently of share amount; unchanged values are still validated.
- [ ] Save creates one immutable revision/event, preserves creator and returns to same detail identity/presentation.
- [ ] Recompute balance/trip/category/date buckets on change, and refresh originating chart/list rather than cached markup.
- [ ] Conflict preserves draft and shows latest/original values; reapply explicitly uses latest version. Concurrent deletion cannot be overwritten or resurrected.
- [ ] Cancel/Escape/Back/resize preserve or confirm draft; failures and duplicate attempts cannot partially update state.

## Mobile, desktop and accessibility

Apply the shared responsive/accessibility rules: phone-first, desktop context preserved, keyboard operation, labels/errors, 44px targets, visible focus, non-color status and correct focus restoration. Verify the relevant journey at 390px and 1280px; no clipped controls at 320px or 200% text.

## Required tests

Integration/E2E edit amount/date/payer/participants/trip/category/note, odd-cent reallocation, stale version, concurrent deletion, timeout retry and N03/N04 context. Run `pnpm format:check`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm build`; obtain independent testing and final-diff review per AGENTS.md.

## Edge states

Cover relevant loading, empty, filtered-empty, invalid input, denied/unavailable, pending, failed and stale states with named seed scenarios. Do not show a fake zero balance while loading or rely on a toast as proof of mutation.
