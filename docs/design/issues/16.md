# Implement household setup and simulated member management

GitHub issue: [#29](https://github.com/haggaikaunda/kami-split/issues/29). Parent: [#13](https://github.com/haggaikaunda/kami-split/issues/13). Design gate: [PR #12](https://github.com/haggaikaunda/kami-split/pull/12).

## User outcome

Users can name a household and understand invitation-only membership and roles.

## References

- [ux-spec.md#u01u02-access-and-household-previews](../ux-spec.md#u01u02-access-and-household-previews)
- [screen-flows.md#n06-repayment-and-account-transitions](../screen-flows.md#n06-repayment-and-account-transitions)

## Included behavior

First household setup, name/default USD, members/roles, pending invite/resend/revoke, owner management and safe removal preview.

## Exclusions

No real invitation email, auth infrastructure, durable membership persistence or expanded privacy guarantees.

## Acceptance criteria

- [ ] Setup validates household name and routes to household; existing expenses retain currency after default changes (only USD enabled now).
- [ ] Owner/member permissions enforced by simulated adapter as well as controls; invitation states are visible and deterministic.
- [ ] Last owner cannot leave without transfer; member with outstanding balance cannot be removed; historical attribution survives simulated removal.
- [ ] Responsive member lists support 3+ people with descriptive controls, focus restoration and error/success announcements.

## Mobile, desktop and accessibility

Apply the shared responsive/accessibility rules: phone-first, desktop context preserved, keyboard operation, labels/errors, 44px targets, visible focus, non-color status and correct focus restoration. Verify the relevant journey at 390px and 1280px; no clipped controls at 320px or 200% text.

## Required tests

Complete the #28 sign-in-to-first-time-setup E2E handoff, then contract/UI tests for roles, setup validation, pending states/retries, last-owner guard, nonzero balance removal and historical member preservation. Run `pnpm format:check`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm build`; obtain independent testing and final-diff review per AGENTS.md.

## Edge states

Cover relevant loading, empty, filtered-empty, invalid input, denied/unavailable, pending, failed and stale states with named seed scenarios. Do not show a fake zero balance while loading or rely on a toast as proof of mutation.
