# Implement simulated sign-in and invitation entry screens

## User outcome

Users can review private-entry and recovery UX without a live identity service.

## References

- [ux-spec.md#u01u02-access-and-household-previews](../ux-spec.md#u01u02-access-and-household-previews)
- [screen-flows.md#n06-repayment-and-account-transitions](../screen-flows.md#n06-repayment-and-account-transitions)

## Included behavior

Clearly labeled sign-in preview, valid email request/sent states, invitation accept/decline, wrong-account/expired/revoked scenarios and setup routing.

## Exclusions

No identity provider, real email/token generation, production authentication or database.

## Acceptance criteria

- [ ] All auth surfaces explicitly indicate preview; no email or credentials are sent/stored.
- [ ] Named scenarios cover valid, used/expired/revoked link, wrong identity and session expiration with actionable recovery.
- [ ] Invitation acceptance changes simulated membership only once; decline stays outside household; access errors reveal no financial fields.
- [ ] After simulated entry navigate to appropriate household or first-time setup and revalidate retained drafts through the adapter.

## Mobile, desktop and accessibility

Apply the shared responsive/accessibility rules: phone-first, desktop context preserved, keyboard operation, labels/errors, 44px targets, visible focus, non-color status and correct focus restoration. Verify the relevant journey at 390px and 1280px; no clipped controls at 320px or 200% text.

## Required tests

UI/adapter tests for each scenario and repeat acceptance/denial; keyboard focus and mobile input checks; explicitly document that tests are not server-auth coverage. Run `pnpm format:check`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm build`; obtain independent testing and final-diff review per AGENTS.md.

## Edge states

Cover relevant loading, empty, filtered-empty, invalid input, denied/unavailable, pending, failed and stale states with named seed scenarios. Do not show a fake zero balance while loading or rely on a toast as proof of mutation.

## Dependencies and readiness

Blocked until the design/documentation PR is reviewed and merged, stable main references are verified, and this issue is approved. Depends on UX-02, UX-03, UX-04. Existing pilot issues #6–#9 are separate and not prerequisites.
