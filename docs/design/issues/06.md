# Implement add-expense flow with visible reconciliation

## User outcome

Users can quickly record a complete, valid split without accidental duplicates.

## References

- [ux-spec.md#e01e03-expense-forms](../ux-spec.md#e01e03-expense-forms)
- [screen-flows.md#n02-add-expense-from-multiple-sources](../screen-flows.md#n02-add-expense-from-multiple-sources)

## Included behavior

Amount-first form, payer/participants, date/currency/category, optional trip/note, equal/exact allocation, all validation and safe submit/cancel.

## Exclusions

No expense editing/deletion or repayment journey, percentage split, receipts or persistence.

## Acceptance criteria

- [ ] Default actor/all active members/equal/USD/current date; trip entry preselects trip with visible editable suggested date.
- [ ] Positive exact amount and complete split reconcile before save; invalid fields have associated errors and first-invalid focus.
- [ ] Included zero-share membership survives mode/participant changes; changing exact mode does not silently discard work.
- [ ] Double submit sends one operation; pending/failed/unknown outcome retains draft and operation ID. Success updates source and keeps filters even when the new record is hidden.
- [ ] Mobile form fills viewport; desktop dialog focuses amount. All exits honor dirty-draft contract.

## Mobile, desktop and accessibility

Apply the shared responsive/accessibility rules: phone-first, desktop context preserved, keyboard operation, labels/errors, 44px targets, visible focus, non-color status and correct focus restoration. Verify the relevant journey at 390px and 1280px; no clipped controls at 320px or 200% text.

## Required tests

Unit/form tests for invalid and odd-cent amounts, equal/exact/no participant/nonparticipating payer, blank description/date, mode switch; E2E P02/P04 plus duplicate and failure retry. Run `pnpm format:check`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm build`; obtain independent testing and final-diff review per AGENTS.md.

## Edge states

Cover relevant loading, empty, filtered-empty, invalid input, denied/unavailable, pending, failed and stale states with named seed scenarios. Do not show a fake zero balance while loading or rely on a toast as proof of mutation.

## Dependencies and readiness

Blocked until the design/documentation PR is reviewed and merged, stable main references are verified, and this issue is approved. Depends on UX-01, UX-02, UX-03, UX-04. Existing pilot issues #6–#9 are separate and not prerequisites.
