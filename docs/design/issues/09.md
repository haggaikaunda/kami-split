# Implement expense deletion confirmation and retained tombstone

GitHub issue: [#22](https://github.com/haggaikaunda/kami-split/issues/22). Parent: [#13](https://github.com/haggaikaunda/kami-split/issues/13). Design gate: [PR #12](https://github.com/haggaikaunda/kami-split/pull/12).

## User outcome

Users can remove an accidental expense without silently erasing its history.

## References

- [ux-spec.md#e02e04-detail-and-deletion](../ux-spec.md#e02e04-detail-and-deletion)
- [screen-flows.md#n03-detail-edit-and-deletion](../screen-flows.md#n03-detail-edit-and-deletion)

## Included behavior

Compact explicit delete confirmation, optional reason, version-checked soft delete, same-URL tombstone and invalidation.

## Exclusions

No permanent purge, restore flow, bulk delete or repayment deletion.

## Acceptance criteria

- [ ] Confirmation names record/amount, explains removed financial effect and retained audit, and initially focuses Keep expense.
- [ ] Keep/close returns to same detail with no extra history step; successful deletion retains URL/revisions and disables edit/delete.
- [ ] Deletion removes totals from balance/contributions/charts/trip without physical record removal and adds an attributed event.
- [ ] Repeated confirmation/retry is idempotent; conflict/already-deleted outcomes are explicit. Back preserves source filters and recomputes empty results.

## Mobile, desktop and accessibility

Apply the shared responsive/accessibility rules: phone-first, desktop context preserved, keyboard operation, labels/errors, 44px targets, visible focus, non-color status and correct focus restoration. Verify the relevant journey at 390px and 1280px; no clipped controls at 320px or 200% text.

## Required tests

E2E Keep and Confirm at phone/desktop, Escape/focus, duplicate delete, stale revision, deleted direct URL and reconciliation of all affected selectors. Run `pnpm format:check`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm build`; obtain independent testing and final-diff review per AGENTS.md.

## Edge states

Cover relevant loading, empty, filtered-empty, invalid input, denied/unavailable, pending, failed and stale states with named seed scenarios. Do not show a fake zero balance while loading or rely on a toast as proof of mutation.
