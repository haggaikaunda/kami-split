# Introduce async data access and deterministic seed adapter

## User outcome

Screens can use realistic asynchronous behavior now and a server adapter later without importing fixtures.

## References

- [data-access.md](../data-access.md)
- [prototype-verification.md](../prototype-verification.md)

## Included behavior

Typed async query/command port, injected session/clock/IDs, one session-local seed store, immutable revisions/events, operation lookup, version checks and deterministic scenario controls.

## Exclusions

No database, migrations, network/auth provider, email, localStorage persistence or production security claim.

## Acceptance criteria

- [ ] Seed the approved sample values/trips and separate three-member fixture; reload/reset semantics are explicit and reset also clears operation history.
- [ ] No component imports mutable seed arrays or direct storage. Queries return snapshots; typed outcomes distinguish validation, conflict, denied, unavailable, precommit failure and unknown completion.
- [ ] Expense/repayment commands atomically commit state/revision/event. Same operation ID and payload returns original result; changed payload with same ID is rejected.
- [ ] Expected-version mismatch or concurrent deletion leaves state unchanged. Timeout-after-commit resolves via same operation ID without duplicate financial effect.
- [ ] Seed access outcomes check simulated actor/role/household at the port boundary; they are not claimed as server security.

## Mobile, desktop and accessibility

This foundation has no UI; expose precise outcomes and stable IDs needed by accessible phone/desktop consumers.

## Required tests

Adapter contract tests for all query/command outcomes, atomicity, duplicate payload reuse, before/after-commit failures, conflicts, denial and deterministic reset. Reuse contracts for future API adapters. Run `pnpm format:check`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm build`; obtain independent testing and final-diff review per AGENTS.md.

## Edge states

Exercise validation, deterministic reset, denial, conflict and duplicate/unknown outcome where supported; see the data-access contract.

## Dependencies and readiness

Blocked until the design/documentation PR is reviewed and merged, stable main references are verified, and this issue is approved. Depends on UX-01. Existing pilot issues #6–#9 are separate and not prerequisites.
