# Implement standalone expense detail and desktop side panel

GitHub issue: [#20](https://github.com/haggaikaunda/kami-split/issues/20). Parent: [#13](https://github.com/haggaikaunda/kami-split/issues/13). Design gate: [PR #12](https://github.com/haggaikaunda/kami-split/pull/12).

## User outcome

Users can inspect and link to a financial record without losing the source context.

- [ux-spec.md#e02e04-detail-and-deletion](../ux-spec.md#e02e04-detail-and-deletion)

- [screen-flows.md#n04-chart-drill-down-chain](../screen-flows.md#n04-chart-drill-down-chain)

## Included behavior

One detail data model in page/panel presentations; all record fields, allocations, creator, trip link and selected revision; missing/deleted states.

## Exclusions

No edit/delete mutation, payment flow, receipt attachments or server authentication.

## Acceptance criteria

- [ ] Direct route and phone render full page; contextual desktop entry opens side panel with Open full page and no redundant history step.
- [ ] Show exact total/currency, payer, participants including zero-share members, date, category, trip, note, creator and complete immutable revision snapshots.
- [ ] Audit-event entry identifies selected revision while making current/deleted status clear. Unavailable ID reveals no record fields.
- [ ] Back/Forward, trip link, repeated visits and resize obey N01/N03/N05/N07; chart-return descriptor supported without stale HTML.
- [ ] Expose edit/delete intent hooks for their later issues, without misleading live controls until connected.

## Mobile, desktop and accessibility

Apply the shared responsive/accessibility rules: phone-first, desktop context preserved, keyboard operation, labels/errors, 44px targets, visible focus, non-color status and correct focus restoration. Verify the relevant journey at 390px and 1280px; no clipped controls at 320px or 200% text.

## Required tests

E2E P05/P09 including direct/missing/deleted URL, full-page replacement, filtered origin, three-member allocation, selected revision and keyboard focus. Run `pnpm format:check`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm build`; obtain independent testing and final-diff review per AGENTS.md.

## Edge states

Cover relevant loading, empty, filtered-empty, invalid input, denied/unavailable, pending, failed and stale states with named seed scenarios. Do not show a fake zero balance while loading or rely on a toast as proof of mutation.
