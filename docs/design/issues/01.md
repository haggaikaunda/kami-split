# Define exact-money and multi-member ledger rules

## User outcome

Every screen derives trustworthy amounts from the same member-based domain rules.

## References

- [data-access.md](../data-access.md)
- [ux-spec.md#e01e03-expense-forms](../ux-spec.md#e01e03-expense-forms)

## Included behavior

Pure typed money parsing/formatting, currency partitioning, explicit participant membership, equal/exact allocation, positions, contributions and expense-based chart selectors.

## Exclusions

No UI, database, transport, percentages, conversion or debt simplification.

## Acceptance criteria

- [ ] Use stable IDs; test a three-member household and a payer who does not participate. No pair-specific domain branches.
- [ ] Reject zero/negative/over-precision/unsafe inputs; document supported bound and deterministic remainder order. $10.01 resolves to 501/500 minor units.
- [ ] Preserve included zero-share participants; allocations and paid totals each equal expense total, and member positions sum to zero per currency.
- [ ] Repayments change positions equally/oppositely and do not increase spending/contributions. Deleted expenses are excluded; current revisions/effective dates drive derived totals.

## Mobile, desktop and accessibility

This foundation has no UI; expose precise outcomes and stable IDs needed by accessible phone/desktop consumers.

## Required tests

Unit/property-style cases for rounding, bounds, equal/exact totals, currencies, three members, zero shares, settlement direction and edit/delete recomputation. Run `pnpm format:check`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm build`; obtain independent testing and final-diff review per AGENTS.md.

## Edge states

Exercise validation, deterministic reset, denial, conflict and duplicate/unknown outcome where supported; see the data-access contract.

## Dependencies and readiness

Blocked until the design/documentation PR is reviewed and merged, stable main references are verified, and this issue is approved. No implementation prerequisite beyond the design merge gate. Existing pilot issues #6–#9 are separate and not prerequisites.
