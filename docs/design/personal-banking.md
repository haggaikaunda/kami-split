# Personal banking interface handoff

This is the planned milestone-one Personal interface, not a statement that banking is implemented or released. The [approved R2 mobile/desktop source and archive](https://github.com/haggaikaunda/kami-split/issues/249#issuecomment-6230033700) establish visual intent. The [product/domain contract](../application/personal-banking.md), live [design issue](https://github.com/haggaikaunda/kami-split/issues/249) and owner decisions govern financial meaning and lifecycle behavior. Current production composition remains documented in the [UI guide](../application/ui.md). Synthetic people, transactions, timestamps and successful demo mutations have no production authority. The owner-approved [C5-v2 amendment](https://github.com/haggaikaunda/kami-split/issues/222#issuecomment-6231452324), scope **plaid-contract-v2 / C5-v2**, supersedes the earlier whole-dataset replacement policy and examples. C1–C4 and R2 layout/navigation remain approved; old synthetic replacement captures do not validate C5-v2.

## Navigation and identity

Extend the existing `WorkspaceNavigation` in `apps/web/src/components/workspace-identity.tsx` and its `workspace/shell.module.css`. Keep one shared shell for Household, Personal, Groups and Account. Preserve the compact bold Kami Grow identity, illustrated accent and destination subtitle delivered by [the shared shell](https://github.com/haggaikaunda/kami-split/pull/315). Private titles and banking data remain inside their authorized read; public navigation must not retain them.

| Surface                                        | Planned behavior                                                                                                                                                                                                                                                                                           |
| ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Mobile, at the existing shell's 600px boundary | Five destinations/actions in order: **Household · Personal · + / Expense · Groups · Account**. The raised plus is a **52px circle**, its visible caption is **Expense**, and its accessible name is **Add expense**. The caption remains visible at narrow widths.                                         |
| Desktop                                        | Household, Personal and Groups use the shared sidebar; retain a fully labeled **Add expense** action and anchor **Account** at the sidebar bottom. Allow sidebar scrolling at short heights without losing Account.                                                                                        |
| Selected state                                 | Household is selected on Household routes; Personal on all Personal pages; Groups includes both ordinary groups and trips; Account is selected on `/account`. Do not retain the current fallback that treats every non-Household/non-Account route as Groups. Use visible state and `aria-current="page"`. |
| Account                                        | Opens the existing full-page Profile at `/account`, with global navigation present. Account is the global navigation label; the Profile page's existing behavior remains. Remove the duplicate header avatar entry when this later shell is implemented.                                                   |
| Personal pages                                 | **Overview / Transactions / Connections** are native route links with a named navigation landmark, not ARIA tabs or demo buttons. Personal initially opens Overview with This month.                                                                                                                       |

Account preserves read-only email, display-name editing/discard/conflict recovery, sign-out/privacy and immediately applied, persisted Light/System/Dark preferences. Add the saved reporting-timezone control to Account as a separate preference operation: initialize from the device once, allow explicit change, and do not change it automatically during travel. These defaults and controls follow [C4](https://github.com/haggaikaunda/kami-split/issues/222#issuecomment-6231114646).

Use `ScopedLink`, `SourceReturn` and `RestoreSource` in `components/groups/navigation.tsx` for exact authorized origin restoration. Returning from Account or a transaction detail must preserve originating page/subpage, applied dates/filters, scroll and focus. Extend source handling for Personal through the same actor-scoped visit ownership; a stale actor's visit must not revive banking content. Restore only after a fresh authorized source response. The document remains the scroll owner; avoid a second independently scrolling page shell.

The global Add expense action retains `useExpenseEntry` and the existing authorized source chooser, Equal/Exact/Percentage intent, dirty drafts, frozen recovery attempts and source return. Personal is never an inferred shared-expense source. In global contexts, require an explicit eligible source; canceling the chooser returns to the exact origin. The prototype's default-first-space form and automatic equal splitting are illustrative only. Connecting a bank or editing a private transaction never creates a shared expense.

## Content, dates and private controls

Overview has one focused **Spending from your accounts** card, its purchases/charges and refunds explanation, coverage nearby, recent activity and a route to all Transactions. Remove the redundant repeated net-spending caption. Transactions uses compact rows with merchant, account identity/mask, posted bank date, exact amount and readable activity/status text. Do not duplicate three overview metric cards above the list. Transfer, Income, Pending, Excluded and Needs review remain readable on phones; distinguish a filtered non-spending view from a successful zero-spending result.

Connect account lives **only in Connections**. First-use Overview/Transactions explain setup and link to Connections, without embedding Link launch actions. Connection cards show selected accounts first, inclusion clearly, and prominent repair when unhealthy. An independently authorized joint account remains full private account activity; neither the UI nor totals imply one person's share.

Overview and Transactions share the applied period: **This month, Last month, Last 60 days, Last 90 days, Year to date, Custom range**. Always display the concrete selected dates. Keep unapplied custom draft dates separate from the applied period: Apply validates and commits; Cancel/Escape preserves the previous applied range. Explain invalid order/bounds adjacent to labeled fields and in the error summary. The domain contract owns inclusive boundaries, reporting timezone, coverage and supported bounds. A preset does not promise that the institution supplied that history. Preserve applied state across page/detail/Account return and isolate it across signed-in actors.

Spending follows [C3](https://github.com/haggaikaunda/kami-split/issues/222#issuecomment-6230994616): posted purchases, bank fees and debit interest minus identified refunds in the refund's posting month. Pending, income, transfers, card repayments, cash withdrawals and unresolved activity remain separate. Posted bank date drives period membership and the main list; optional authorization date belongs in detail. Shared expenses, allocations and repayments are never added to this M1 account-activity amount.

Transaction detail opens read-only. Explicit Edit enables the approved private single-row category, activity type, note, exclusion/inclusion and review controls. Show when an effective value overrides the bank classification and offer reset to the current bank-derived value. Keep bank amount/date and source facts immutable; distinguish provider processing status from private review status. Save uses the contract's revision/conflict rules; response uncertainty is not a successful save. Cancel and navigation protect dirty drafts, with a safe keep-editing choice and focus restoration. Reset is an explicit private mutation with the same pending/conflict/recovery behavior.

M1 has background collection and in-app notices. It excludes bulk edits, charts, budgets, search, receipts, private manual expenses, account-balance dashboards, email/push and bank-transaction sharing. Existing shared manual expense entry remains available. A mockup's controls or arithmetic do not broaden these boundaries.

## State and recovery handoff

Use server-owned availability, lifecycle and coverage rather than inferring success from visible rows, a Link callback or elapsed time. Keep technical retry and connection management in their owning operations.

The owner-approved [C5-v2 transition policy](https://github.com/haggaikaunda/kami-split/issues/222#issuecomment-6231452324) adds a deliberate sequence under Connections. Prefer existing-connection repair. For each ambiguous account, offer **Replace existing**, **Different account**, or **Cancel**, showing only this user's accounts. A staged replacement contributes nothing. Keep the prior reporting plan visible with truthful stale/repair context until a usable import is ready.

Provide a labeled transition-date field and explicit confirmation: **Keep existing history through D, inclusive; use the new connection after D**. Validate a real nonfuture posted-bank calendar date using the saved reporting timezone; show field errors and an error summary. A suggested latest old posted date is not coverage proof. On repeated transitions, show all retained intervals and require the latest date to follow the preceding transition; earlier intervals remain intact.

The preview shows retained/new/archived periods and row counts, original annotations that stay effective, old rows after D becoming archive-only, pending effects, current/proposed totals, overlap and known/unknown gaps. Similar overlapping rows are not proven duplicates. Explain that older retained history remains in normal reporting even outside the bank's returned window. For D = September 30, an original excluded/noted September 20 $100 purchase plus a replacement September representation and October 2 $50 produces $50 spending: retain the original September exclusion/note and use only the new October row. Do not claim complete coverage from that example or from a successful import.

**Confirm transition** and **Cancel** are explicit actions. Unavailable/failed/unknown imports cannot be confirmed. Changed plan/import/data/annotation/lifecycle revisions require a refreshed preview and confirmation; cancel/conflict leaves the prior plan current. During submission prevent duplicate actions and retain the preview. If the response is uncertain, read operation status before retrying. Confirmation freezes retired source facts and fences only that account, preserving sibling accounts. The active binding alone supplies pending rows; retired pending rows remain archive-only. Later corrections in preserved periods show a historical-discrepancy notice; a changed posted date crossing D warns of a possible gap/duplicate and refreshes affected reads. No automatic matching or correction action is implied.

After activation, Connections offers **View recovery archive**, **Change latest transition date**, and **Restore preceding plan**. Recovery is an explicit new plan revision. Preview rows/annotations leaving current reporting, preserve them in the archive, and show retained latest valid private edits on restored sources. Changing the latest D must remain after the preceding transition. A purged source blocks exact restoration. Explain that recovery does not restart credentials, provider permission, selection or workers, or recover deleted data; stale/partial/disconnected context remains visible. Keep recovery pending/conflict/uncertain-result behavior equivalent to transition confirmation.

Archive navigation opens a clearly labeled, separately scoped list/detail with plan/connection version, captured dates and annotation provenance. Preserve applied archive filters and origin on return, with **Back to current activity**. Archive references add no current list/count/review/spending contribution. For a retained row still current, show immutable snapshot provenance and a link to its single current editable row; do not offer an independent archive annotation copy. Archive-only rows retain approved private edits, visibly affecting no current totals until explicitly restored. Historical snapshot versions remain immutable. Deletion confirmation names both current and archived private history/annotations in the selected scope, preserves sibling accounts and does not alter shared expenses. Use a mobile sheet/page and desktop contextual panel with labeled fields, explicit return/focus restoration, reachable actions and pending/conflict/uncertain-result states.

| State                                    | Required presentation and action                                                                                                                                                                                                                                         |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| First visit, no selected accounts        | Private-context empty state; Overview/Transactions link to Connections; initial connect action only there. Do not show a fabricated zero total.                                                                                                                          |
| Initial authorized read pending          | Public shell and generic page identity, neutral geometry and one polite loading status; private values remain absent. Reuse production delayed/long-loading behavior.                                                                                                    |
| Importing                                | State that history is importing and which activity is available; suppress an unavailable complete total. A recent row does not prove import completion.                                                                                                                  |
| Ready, complete, no matching activity    | Clear empty result for the applied period/filters. A zero total is valid only when the server establishes complete eligible coverage and arithmetic. Provide filter reset when relevant.                                                                                 |
| Partial history                          | Put coverage and missing-history explanation next to affected amount/list/count. A partial amount is labeled as such; never present it as a complete period or silently treat unavailable history as zero.                                                               |
| Stale data or temporary read/sync error  | Explain the affected scope and known freshness; retain previously imported history according to the authorized lifecycle contract. Retry the owning read/sync action; do not replay uncertain mutations. Suppress protected content whenever authorization is uncertain. |
| Reconnect needed                         | Show retained history plus a clear warning that recent data may be missing; route to the affected connection's repair. Reconnect is explicit and must not silently broaden selected accounts.                                                                            |
| Canceled/failed/expired Link             | Return to the owning connection state, retain applied selection/history and offer an appropriate restart. A duplicate callback or lost exchange response enters recovery, not a second connection or fake completion.                                                    |
| Disconnected or externally revoked       | State that updates stopped and imported private history remains. Reconnect and explicit history deletion are distinct actions. Neither disconnect nor revocation silently deletes history.                                                                               |
| Account selection save pending/conflict  | Show exactly the proposed accounts, prevent duplicate submission, keep errors/recovery beside the action and reread when the result is uncertain. Omitted/unsupported accounts are not silently included.                                                                |
| Private edit save pending/conflict/error | Keep the draft, immutable bank facts and prior committed value clear. Resolve revision conflicts explicitly; do not overwrite fresh source facts with a stale form.                                                                                                      |
| Explicit history deletion                | Separate confirmation explains affected institution/history/private annotations, stops updates as specified by the lifecycle contract and does not imply deletion of separate shared expenses. Do not claim completion while server deletion is uncertain.               |
| Access loss, logout or actor change      | Remove protected content and drafts/visits belonging to the old actor immediately; ignore late responses. Show generic access/error recovery without institution, account, merchant or amount leakage.                                                                   |

No routine refresh button, instant-bank-update promise or mock successful reconnect is implied. Preserve existing pull/foreground refresh ownership and request coalescing. Error messages and in-app notices must avoid raw provider payloads or credentials.

## Responsive and accessible implementation requirements

Keep the shell's existing 600 CSS-pixel breakpoint and measured safe-area/chrome contract. R2's preview-only 490/730px container transitions are visual references, not replacements for production breakpoints. Feature content should reflow using its actual available container width. The mockup's rounded device frame, maximum width, absolute overlays and fixed minimum height are preview geometry; production must fill the available page, scroll naturally and work at short viewport heights.

At **320, 390 and 440 CSS pixels**, render the actual application container and verify all five labels, the 52px action and selected states without horizontal page scrolling or overlapping targets. Keep meaningful labels; wrap and grow the navigation/rows instead of hiding text or shrinking it to illegibility. Allow long institution/account names, merchant names, concrete date ranges and exact amounts to wrap or use a purpose-built full-value presentation. Form actions remain reachable above safe areas and the keyboard; enlarged text/short viewports release sticky positioning when necessary.

Give transaction merchant/account metadata an explicit full usable column; when space is tight, place the amount below it rather than reserving a wide right column that reduces names to a few letters per line. Hiding a category must not implicitly move the remaining grid items. Keep signs and currency visible with the complete exact amount; let currency occupy its own line and reflow at intentional boundaries when needed, without truncating digits or shrinking below readable body text. Connection status such as Included reserves a readable width beside long names. Date/help/View all/Manage accounts controls use at least 44px targets even where the sample's original controls are smaller.

At **200% text on desktop**, enlarge actual computed text rather than applying a screenshot transform or only changing the root size while pixel text remains unchanged. Recheck sidebar labels/Account bottom placement, full Add expense, dates, hero equation, transaction amounts, connection cards, sheets and confirmation actions. Also check a short viewport and browser zoom/reflow. Avoid fixed panel heights and clipped full-page detail. Let dense columns stack before labels or money collide.

Allow the sidebar to widen or reflow enough for full-word Household, Account and Add expense labels; do not solve enlargement with arbitrary intra-word breaks. Stack the spending equation below the main amount and recent-activity columns when needed. Content and sidebar growth must retain natural document scrolling and reachable bottom Account placement. Temporary preview sizing is evidence of a proposed adaptation, not production CSS to copy verbatim.

| Interaction                               | Required semantics and focus behavior                                                                                                                                                                                                                                       |
| ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Global and Personal navigation            | Native links with visible text, distinct landmarks and selected state. Tab follows visual/logical order; Enter navigates. A pending cue does not replace the committed `aria-current`.                                                                                      |

Desktop contextual placement stays inside the viewport and preserves equivalent keyboard access. |
| Transaction detail                        | Keyboard-operable labeled row/link; read-only detail heading receives appropriate route/panel focus. | Status and error                          | One purposeful live announcement per event, errors near their controls, decorative skeletons/icons hidden, no focus theft during loading. Meaning remains clear without color.                                                                                              |
| Appearance                                | Check Light, explicit Dark and System under both OS schemes. Focus ring and controls remain visible over all surfaces/artwork; account/actor switches must not inherit another person's saved state.                                                                        |
| Targets and motion                        | Use the production 44px minimum interactive target, including help, filter chips, close and inline repair controls. Keep the approved 52px creation circle. Reduced motion makes loading/transition decoration static and never affects access to content.                  |

Visual examples do not prove browser semantics, authorization, persistence, provider behavior or release readiness. Implementation verification must exercise real routes and controlled authenticated fixtures, including keyboard-only use, long content, actual text enlargement, every state above, Account return from filtered Personal activity and expense-source cancellation/recovery. Keep screenshots, observations and acceptance reports on the owning issue/PR or temporary storage, separate from this maintained guide.
