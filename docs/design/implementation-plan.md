The dependency graph is acyclic. Foundations can proceed independently once prerequisites are met. Each journey owns its validation/accessibility/recovery; final verification issues integrate and audit rather than defer correctness. GitHub issue bodies mirror these versioned acceptance criteria. If approved scope changes, update both.

Database persistence and real authentication are deferred. Existing greeting pilot issues #6–#9 remain separate; do not close, alter or reinterpret them as part of this rollout.

4. Use the [prototype walkthrough](prototype-verification.md) and [navigation contract](screen-flows.md) to validate behavior; record independent tester/reviewer evidence per AGENTS.md.
5. Complete the tracker only after all child acceptance criteria and final verification pass.
