# Expense editing

Issue [#21](https://github.com/haggaikaunda/kami-split/issues/21) adds Edit expense to current detail records. The existing expense form and integer validation are shared with creation. The complete record is prefilled, including explicit participant membership, zero shares, payer, effective date, trip, category and note. The original immutable snapshot and expected version are retained in the session draft; refreshes never silently rebase it.

A successful update creates a revision and attributed activity through the async port, preserves the creator, and refreshes derived queries. Per-visit navigation returns to the same detail URL and presentation, preserving selected audit revision and source query state. Direct edit links have an explicit fallback to that expense. Creation retains its existing behavior and recovery tests.

Conflicts show complete original, latest and draft values. Reapply keeps the user's full draft and explicitly targets the displayed latest version; it does not itself save. A subsequent concurrent change causes another conflict. Deleted records remain read-only and cannot be resurrected. Unknown completion freezes the original command and operation until status lookup resolves it, and session-owned commands finish safely after the form unmounts.

Tests cover all-field editing, unchanged-field validation, odd-cent allocation, manual zero membership, immutable revisions and creator, changed actor attribution, date/trip/balance recomputation, conflict/reapply, concurrent deletion, timeout recovery and pending duplicate/navigation safety. Browser integration verifies the detail presentation and source restoration separately. The implemented [spending charts](spending/README.md) and [trip detail](trips/detail.md) use the same shared snapshot invalidation and selectors.

Independent browser verification used the production preview at 1280px and 390px, with a 320px reflow check. Starting from the selected revision-1 contextual detail, changing the total to 100.01 USD, effective date to October 1, trip to Maui and note returned to the exact same detail visit and retained the selected activity. The current record showed revision 2, original creator Mizenin, editing actor Kaunda and exact 50.01/50.00 allocations; Overview refreshed to 50.01 USD owed and 5,142.21 USD total spending. A simulated second editor showed original revision 2, latest revision 3 and the preserved draft, blocked Save and focused the comparison heading. Explicit reapply then saved revision 4 with the retained date/note and restored focus to Edit expense on phone. At 320px the document remained 320px wide and the dialog 318px wide. A reset seen during development hot reload did not reproduce in the stable production build.
