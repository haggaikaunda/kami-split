# Approved journey evidence matrix

This matrix traces the approved [P01–P10 walkthroughs](../design/prototype-verification.md) and [N01–N07 navigation contract](../design/screen-flows.md) to implementation evidence. The design prototype defines expected behavior; it is not evidence that the production application passed. All financial/access behavior is a session-only simulation.

Test paths below are relative to the repository root. Quoted names identify actual tests, rather than proposed coverage. Feature documents preserve the earlier implementation PR browser records; those records are historical evidence, not a new #31 device run. Fresh #31 browser evidence and screenshots are recorded separately by the primary verifier in the [final integrated report](README.md).

## Independent #31 source audit

The bounded changes address the prior audit: nonshrinking modal Close button; trip-card focus ring on the unclipped parent; 44px `shell-action` targets on entry, repayment History and filtered-empty trip links; `viewport-fit=cover`; and a minimum 70% dark trip-cover scrim. No financial or navigation state behavior is changed by these fixes.

Contrast was calculated from sRGB relative luminance, without screenshot sampling. Ink on white/canvas/balance is **13.42 / 12.45 / 11.50:1**; muted text **6.29 / 5.84 / 5.39:1**; primary **7.92 / 7.35 / 6.79:1**; focus **6.41 / 5.94 / 5.49:1**. Danger text on its error surface is **6.78:1**. The trip overlay `rgb(12 38 32 / 70%)` over the worst-case white image produces RGB **84.9, 103.1, 98.9**, giving white text **5.98:1**; the 90% endpoint gives **11.86:1**. Thus image brightness no longer defeats text contrast anywhere along this scrim. Decorative border contrast is 3.10:1 on white, 2.87:1 on canvas and 2.65:1 on balance; input and secondary-control interiors are white. Decorative dividers do not independently establish a text/control contrast failure.

Source inspection confirms global reduced-motion overrides; 100dvh dialogs with four safe-area insets; bottom-nav/workspace/sticky-form inset handling; system-font fallbacks; image-error initials/abstract covers; zero-baseline chart geometry with separate 44px targets; named keyboard-focusable scroll regions; captions and scoped table headers; exact currency/amount/count labels. It does not prove browser rendering, physical touch target measurements, screen-reader output or actual iOS keyboard/notch behavior. Automated accessibility scans have their own scope and limitations and are reported by their owning verifier.
