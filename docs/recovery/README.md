# Cross-journey recovery

Issue [#30](https://github.com/haggaikaunda/kami-split/issues/30) integrates the existing async mock port and session-owned requests. Simulation controls exercise actual adapter states; they do not manufacture a success toast. All data remains session-only, without production authentication or persistence.

## Boundaries

A known offline failure publishes no expense, repayment, revision or event. An unknown result freezes the original operation and draft. Recovery queries that operation before any repeat write, revalidates the original household/actor, and applies at most one financial effect. Reset/discard cannot abandon unresolved requests. Expired/denied access hides private financial fields while retaining the session draft; restoring the original session revalidates it before submission. Old reads/completions cannot replace a newer source or steal navigation.

A cross-feature safeguard prevents edits or deletion from reopening debt for an inactive member after their balance was settled and access removed. The candidate expense, revision and event are staged together; direct obligations are checked in each supported currency before the atomic state swap. Rejection publishes no partial audit or financial changes and leaves the operation unbound for a corrected request. Nonfinancial corrections remain possible. This preview intentionally does not add membership restoration or silently assign the former member a new identity.

Unknown expense, repayment and trip forms now focus their explicit operation-recovery action after the parent dialog opens. An unmounted form or closed/inert background cannot take focus. This addresses a live-browser finding where disabling Save left keyboard focus on the web area.
